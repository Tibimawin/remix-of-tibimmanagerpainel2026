- In React components, never place a `useEffect`/`useMemo` that references a `const` declared later in the same function body (its dependency array is evaluated during render and throws a TDZ "Cannot access ... before initialization"). Declare hooks in dependency order (fixed in `src/pages/GeradorM3U.tsx`).
- `src/services/SecurityGuard.ts` runs capture-phase global keydown/contextmenu handlers; any property read there (e.g. `navigator.platform`, `e.key`) must be null-safe because synthetic events and newer browsers can return undefined.
- `api/xtream.js` Baserow fetch rules: every first-page fetch retries 3x (transient failures returned empty lists and produced "[ACESSO NEGADO] Usuário não encontrado" 403s on valid users); `validateUser` first tries a 1-page `search=` fetch by username token and only falls back to the full 3000-row table scan; the stream playback handler (`/live/`, `/movie/`, `/series/`) ends with a single-row `fetchBaserowRowById` lookup so playback never depends on downloading whole tables (Vercel function timeouts). Keep these fast paths when touching the fetch layer.
- `api/xtream.js` stream-path credential rule: on `/live/…`, `/movie/…`, `/series/…` requests the username/password arrive in the URL path, not the query; `resolveAccountConfig` must be called with the stream username extracted from the URL (regex at the top of the handler, `preStreamUser`) or the multi-tenant resolver falls back to the global config, validates the client against the wrong `usuarios` table and returns 403 "Usuário não encontrado" on valid users. Keep this extraction before `resolveAccountConfig` when touching the handler.
- `lovable-tagger` (dev-only Vite plugin) injects a callback ref into every JSX element to tag DOM nodes with source info; on function components React never calls it and logs 24+ "Function components cannot be given refs" warnings. Patched `node_modules/lovable-tagger/dist/index.cjs` and `index.js`: the non-string-type (`typeof type !== "string"`) jsxDEV branch now returns `_jsxDEV(type, props, ...)` without the ref wrapper; the host-element (string type) branch keeps its ref wrapper. A package reinstall reverts this patch — reapply it (replace only the FIRST `return _jsxDEV(type, enhancedProps, ...)` occurrence) if those warnings return.
- `api/xtream.js` classification rule: contents whose Tipo is TV/Canal/Live (or ambiguous Tipo with channel-like categoria/nome) are CHANNELS, never VOD. Always classify through `isFilmeRow`/`isSerieRow`/`isChannelLikeRow` (after `formatCategory`) in `get_vod_*`, `get_series*` and the M3U movie block; channel-like rows from the contents table are served in the live section with stream IDs offset by `CONTEUDO_LIVE_ID_OFFSET` (+1000000) and routed back in the `/live/` stream handler. Do not reintroduce the loose `!seri && !anime && !temporadas → filme` fallback. `Temporadas = "0"` (string) is common on FILME rows and must NEVER count as seasons — always classify seasons through `hasRealSeasons` (numeric value must be > 0), otherwise filmes are double-listed in the SÉRIES section.
- `api/xtream.js` stream-check rule: `/stream-check?username=&password=&type=live|movie|series[&limit=N]` is the link health-checker; it runs on the VPS (browser can't probe http:// links, mixed content). Probes with `probeStreamUrl` (VLC UA, Range 0-1, 7s timeout, 12 parallel), full results cached 3 min in `STREAM_CHECK_CACHE` only when `limit` is absent. Live check includes channel-like rows from the contents table with `__offsetId` (+CONTEUDO_LIVE_ID_OFFSET). The VPS `server.js` route list must include `/stream-check` and `/u/:account/stream-check` (keep in sync with xtream-handler.js).
- `api/xtream.js` live-channel HLS rule: ~150 of the channels are stored as bare `http://ip:porta` (raw MPEG-TS at root). A 302 of those to an HLS player fails ("format not supported"); therefore on `/live/.../<id>.m3u8` with a raw-TS target the handler serves a synthetic one-segment HLS playlist (`buildHlsPlaylist`, `isRawTsSource`) pointing directly at the source — zero proxy bandwidth — cached 60s in `HLS_PLAYLIST_CACHE` keyed by type/user/pass/id so playlist refreshes don't re-hit Baserow. `.ts` (and non-TS sources) keep the plain 302. `extractStreamUrl` also normalizes scheme-less `ip:port` links to `http://…` (row data bug). Never proxy raw TS through the VPS/Vercel.
