# Project Notes

`api/` has its own `AGENTS.md` to read before changing files there.

- Payment reconciliation invariants (`src/services/PaymentReconciliationService.ts`): the Firestore `financialRecords` record created at purchase time is the source of truth for `isFeatureUnlockOnly`/`requiredFeature`/days — heuristics by price/description are only a fallback when no record exists. A feature unlock (`Desbloqueio: X`, `source: feature_unlock`, or explicit `requiredFeature`) must NEVER extend/overwrite `expiryDate` or add subscription days; it only adds the feature to `enabledFeatures`. If the user has no expiry anywhere, do not fabricate one. All `financialRecords.userEmail` writes must be lowercased (reconciliation queries by lowercase email; mixed-case emails previously made paid plans never activate). Reconciliation queries also try the original-case email variant for legacy records.

- In React components, never place a `useEffect`/`useMemo` that references a `const` declared later in the same function body (its dependency array is evaluated during render and throws a TDZ "Cannot access ... before initialization"). Declare hooks in dependency order (fixed in `src/pages/GeradorM3U.tsx`).
- `src/services/SecurityGuard.ts` runs capture-phase global keydown/contextmenu handlers; any property read there (e.g. `navigator.platform`, `e.key`) must be null-safe because synthetic events and newer browsers can return undefined.
- `lovable-tagger` (dev-only Vite plugin) injects a callback ref into every JSX element to tag DOM nodes with source info; on function components React never calls it and logs 24+ "Function components cannot be given refs" warnings. Patched `node_modules/lovable-tagger/dist/index.cjs` and `index.js`: the non-string-type (`typeof type !== "string"`) jsxDEV branch now returns `_jsxDEV(type, props, ...)` without the ref wrapper; the host-element (string type) branch keeps its ref wrapper. A package reinstall reverts this patch — reapply it (replace only the FIRST `return _jsxDEV(type, enhancedProps, ...)` occurrence) if those warnings return.
- Per-user app name (client rebranding): `AppNameContext.tsx` asks the client for their app name on first login (dialog in `AppNamingDialog.tsx`, shown via `AppNameGate` in `Layout.tsx` when `needsAsk`), stores it in Firestore `users.appStoreName` (write is quota-tolerant — localStorage `tibim-app-name-<uid>` is the source of truth for display) and shows it in the sidebar brand, the header fallback title and `document.title`. Editable in Configurações → Aparência (`AppNameSettings.tsx`). Never hardcode a brand name in `UserSidebar`/`UserHeader` — use `useAppName().appDisplayName`.

Never fall back to legacy global localStorage configs (`admin-config`, `import-config`), `systemConfig/baserow`, or other users' `userConfigs` docs; `UserConfigService.migrateFromLocalStorage` is intentionally a no-op.
